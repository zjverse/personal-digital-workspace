# 项目思路流程记录

本文记录本项目从最初设想到最终版本的收敛过程。它不是功能清单承诺，而是一次项目决策复盘。

## 1. 初始设想

项目最初被设想为一个完整的个人数字工作系统，用于统一管理网址收藏、AI 工具、VPS、支付入口、海外账号、开发工具和数字资产入口。

初始设想包含很多后台能力，例如登录、管理后台、增删改查、智能分类、导入历史、数据导出和恢复。

在实际讨论和试用过程中，目标逐渐收敛：当前最需要的是一个高效、好看、可长期维护的个人网址展示页，而不是复杂后台系统。

## 2. 最终定位

最终版本定位为：

一个私用的网址工作台，负责展示、搜索、导入和打开书签。

当前版本只保留：

- 首页展示
- 多级目录
- 书签导入
- 常用网址
- 常用排序
- 全局搜索
- 多选打开
- favicon 兜底
- 本地 SQLite 存储
- 部署配置

当前代码也按这个目标完成了瘦身：后端数据库只保留 `categories`、`websites`、`favorites` 三张表。

当前版本不保留：

- 登录
- 退出
- 后台管理
- 网站 CRUD 管理界面
- 智能分类
- 导入记录前台展示
- 数据导出前台展示

这样可以让项目更轻、更稳定，也更贴合日常使用。

## 3. UI 方向

UI 参考了 `https://009tg.com/` 的紧凑网址导航布局，但不是复制其内容。

最终采用：

- 左侧深色目录栏
- 右侧浅灰背景
- 白色紧凑卡片
- 金色点缀
- 大屏自适应多列
- 卡片只展示名称和所属分类

早期的暗黑玻璃风格被替换掉，因为它更像展示型后台，不如紧凑卡片适合大量网址入口。

## 4. 目录与展示逻辑

导入后不做智能分类，完全尊重浏览器书签结构。

展示规则：

- 首页默认打开“常用网址”
- 左侧保留完整书签目录层级
- 一级目录下显示二级目录
- 二级目录下继续显示三级目录
- 没有更深层级时展示该目录下网址
- 当前目录有子目录时，右侧按子目录分组展示
- 搜索时全局搜索全部网址，不受当前目录限制

这个规则保证导入结果和原始书签栏一致，用户后续也容易理解。

## 5. 导入逻辑

导入是当前版本唯一保留的数据维护入口。

支持：

- Chrome HTML 书签文件
- Edge HTML 书签文件
- Brave HTML 书签文件
- Chrome JSON 书签结构

导入原则：

- 一次性导入完整文件
- 严格按文件顺序导入
- 保留目录层级
- 保留常用网址
- 不上传真实书签文件到 GitHub

导入解析器已经从“按行解析”改成“按 HTML 标签顺序扫描”。这样即使书签 HTML 被压缩成一整行，也能完整解析。

## 6. 常用网址

常用网址是首页默认视图。

设计原因：

- 不是每次都需要看所有目录
- 高频入口应该第一时间出现
- 用户可以手动决定哪些网址重要

功能规则：

- 星标加入常用
- 再次点击星标移出常用
- 常用网址支持上移和下移
- 重新导入书签时，如果 URL 仍存在，常用状态会保留

## 7. 搜索

搜索是全局搜索。

无论当前停留在哪个目录，只要输入关键词，就搜索全部网址。

搜索范围包括：

- 标题
- URL
- 描述
- 域名
- 所属目录

## 8. 多选打开

用户可以勾选多个网址，然后点击“打开选中”。

单个网址点击时在当前页面跳转。

批量打开多个网址时必须打开多个标签页，这是浏览器限制。为了减少只打开一个页面的问题，系统为每个链接使用独立窗口名。如果浏览器拦截弹窗，会保留未打开的选择并提示用户允许弹窗。

## 9. Favicon

图标处理采用兜底策略：

- 优先使用书签文件自带 icon
- 可运行脚本尝试抓取真实 favicon
- 尝试网页 `<link rel="icon">`
- 尝试 `/favicon.ico`
- 使用 Google favicon 服务兜底
- 仍失败时生成本地字母图标

目标是不让卡片出现空白图标。

## 10. 隐私与 GitHub

这个项目会处理个人真实书签，因此上传 GitHub 前必须保护隐私。

不允许提交：

- 真实浏览器书签 HTML / JSON
- SQLite 数据库
- `.env`
- 日志
- 构建产物
- node_modules
- 系统缓存

允许提交：

- 项目代码
- 部署配置
- README
- docs 文档
- examples 中的公开示例书签

当前示例书签是伪造内容，只用于演示导入格式。

## 11. 当前版本总结

当前版本是一个面向个人使用的轻量网址工作台。

它解决的问题是：

- 书签太多，浏览器原生书签栏不好整理
- 需要按照原目录结构展示
- 需要高频入口
- 需要快速搜索
- 需要多选打开
- 需要可部署和可备份

它暂时不解决的问题是：

- 多用户权限
- 后台管理
- 在线编辑书签
- AI 自动分类
- 团队共享

后续如果需要扩展，可以在这个轻量版本上继续加，而不是一开始就把系统做重。
